# Module 4 — AIS Ingestion + Vessel Attribution

Given Shazmeen's (Module 3) probable source region and time window, ingests
AIS vessel-position data, reconstructs trajectories, and ranks candidate
vessels by spatial/temporal/drift compatibility — decision support, not a
legal determination.

## Install

```
pip install pandas numpy geopandas shapely pyyaml pytest
```

No external API/credentials are needed anywhere in this module — it only
reads local CSV/JSON files.

## Run

From the `ais_attribution/` directory:

```
python -m src.ranking_pipeline
```

This uses the bundled synthetic demo data by default. To run against a
different source:

```
python -m src.ranking_pipeline \
    --source_estimate path/to/source_estimate.json \
    --ais path/to/raw_ais.csv \
    --ais_source_format marinecadastre \
    --output_dir path/to/outputs
```

`--ais_source_format` can be omitted — the pipeline auto-detects
MarineCadastre vs. synthetic column layouts from the file itself. **This is
the point of the whole module's design**: swapping in a real incident's AIS
data later means pointing `--ais` at a new file and (if it's neither
MarineCadastre nor the synthetic format) adding one more column-mapping
dict to `normalize_schema.py` — never touching `ranking_pipeline.py`,
`scoring.py`, or any of the filtering/reconstruction logic.

`run_pipeline()` can also be called directly as a Python function (its
actual documented interface for Module 5's orchestrator) — see its
docstring in `src/ranking_pipeline.py` for every parameter.

**Note:** run as a module (`python -m src.ranking_pipeline`), not
`python src/ranking_pipeline.py` directly — the package uses relative
imports internally so it can be copied into a different repository without
needing `src/` itself on `sys.path`.

## Swapping in a real incident's AIS data later

1. Get the real incident's AIS export as a CSV.
2. If its columns don't match MarineCadastre's or the synthetic generator's,
   add one dict to `src/normalize_schema.py` (`<INCIDENT>_COLUMN_MAP`) and
   one `elif` branch in `detect_source_format()`. That's the only code
   change ever required.
3. Run `python -m src.ranking_pipeline --ais path/to/incident.csv --ais_source_format <incident> --ais_data_source_label <incident_name>`.
4. `candidate_ranking.json`'s `ais_data_source` field will now read
   `<incident_name>` instead of `"synthetic"` — this is a data swap, not a
   code change, exactly as the project's design goal requires.

## Input schema (from Module 3 / Shazmeen)

`source_estimate.json` — the fields this module actually reads:
`scene_id`, `region_id`, `backtracking_valid`, `no_oil_detected`,
`probable_source_region` (**GeoJSON Point**: `{"type":"Point",
"coordinates":[lon,lat],"radius_km":float}`), `probable_source_time_window`
(`{"start","end"}` ISO8601), `drift_trajectory` (optional — list of
`{"timestamp","lat","lon"}`, ordered latest-first per Module 3's actual
backward-trajectory convention).

If `backtracking_valid` is `false` or `no_oil_detected` is `true`, the
pipeline short-circuits and writes a schema-valid `candidate_ranking.json`
with `ranked_candidates: []` and no AIS analysis attempted.

Raw AIS input: any CSV whose columns match a registered adapter in
`normalize_schema.py` (MarineCadastre's real column names, or the
synthetic generator's own). Required after normalization: MMSI, timestamp,
latitude, longitude. SOG/COG/heading/vessel_name/vessel_type are used where
available but never required.

## Output schema

`candidate_ranking.json` — see spec §9 / `build_output()` in
`ranking_pipeline.py` for the exact schema: `scene_id`, `region_id`,
`ais_data_source`, `search_bbox` (`min_lat`/`max_lat`/`min_lon`/`max_lon`),
`search_time_window`, `total_vessels_in_window`, `ais_coverage_note`,
`ranked_candidates` (each with `rank`, `mmsi` (string), `vessel_name`,
`vessel_type`, `closest_approach_km`, `closest_approach_time_utc`,
`temporal_compatible`, `trajectory_drift_compatibility_score`,
`ais_completeness_score`, `composite_score`, `score_type` — always
`"heuristic_composite_score"`, never `"probability"` — and
`evidence_summary`), a hardcoded `disclaimer`, `backtracking_valid`,
`no_oil_detected`.

`normalized_ais_tracks.geojson` — WGS84 (EPSG:4326) point features for
every AIS record inside the search window.

## Verified explicitly (not assumed)

- **AIS completeness never affects `composite_score`** — inspected
  `calculate_composite_score`'s actual parameters; `ais_completeness` is
  not among them (see `tests/test_scoring.py::test_ais_completeness_never_used_as_score_input`).
- **Scores are never labeled "probability"** — `score_type` is hardcoded
  `"heuristic_composite_score"` in every output path.
- **The disclaimer is a hardcoded, tested part of every output**,
  including both short-circuit paths and the zero-candidates path.
